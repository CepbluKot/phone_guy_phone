Браузерная и SIP-телефония с голосовым профилем Phone Guy. Браузерные клиенты и
физические телефоны соединяются через Asterisk; Go управляет звонками, а RVC
обрабатывает голос для настроенных телефонных номеров.

> Результаты последней проверки звонка и актуальные ограничения собраны в
> [журнале приёмки](docs/BROWSER_CALL_ACCEPTANCE.md) и
> [статусе развёртывания](docs/LIVE_STATUS.md).

## 🚀 Демо

Точные веб-адреса, SIP-узел и порты задаются конфигурацией конкретного развёртывания.

| Интерфейс | Адрес | Назначение |
| --- | --- | --- |
| Браузерный телефон | Публичный URL задаётся конфигурацией | Вход в телефонный интерфейс; требуется авторизация владельца |
| Внутренний телефон | Внутренний URL задаётся конфигурацией | Доступ через VPN |
| Админка | URL задаётся конфигурацией | Управление телефонными профилями и просмотр состояния; доступ через VPN |
| Конференция | URL задаётся конфигурацией | Страница прослушивания; микрофон не запрашивается |
| SIP для физических телефонов | SIP-узел и порт задаются конфигурацией | Используются TLS и SRTP; регистрацию аппарата из внешней сети ещё предстоит подтвердить |

## 🧭 Общая идея

Система разделяет управление звонком и обработку его аудио. Браузерный телефон
использует SIP.js и WebRTC, физические аппараты подключаются по SIP. Go-сервис
ведёт телефонные сессии и управляет вызовами через ARI, а Asterisk обрабатывает
SIP-сигнализацию и соединяет медиаканалы.

Для номеров с профилем Phone Guy аудио направляется на RVC-сервис. При сбое
внешнего медиасоединения система повторяет подключение. Если обработку голоса
восстановить не удаётся, звонок может продолжиться с прямым телефонным аудио;
преобразование голоса для такого вызова отключается.

## 🧩 Основные компоненты системы

### 👤 Пользовательский слой

| Компонент | Назначение |
| --- | --- |
| Браузерный телефон | Регистрация SIP-клиента, список абонентов и управление звонком |
| Admin UI | Настройка телефонных профилей и просмотр состояния телефонов и Asterisk |
| Страница конференции | Прослушивание конференции без захвата микрофона |

### ☎️ Управление звонками

| Сервис | Назначение |
| --- | --- |
| Go (`cmd/voice-web`, `internal/`) | API, браузерные сессии, маршрутизация и жизненный цикл звонков |
| Asterisk (`conference/asterisk/`) | SIP/PJSIP, медиаканалы, мосты и управление через ARI |
| TURN (`deploy/coturn/`) | Ретрансляция WebRTC-медиа, когда прямое соединение недоступно |

### 🎙️ Обработка голоса

| Компонент | Назначение |
| --- | --- |
| RVC service (`rvc_service/`) | Преобразование аудио моделью Phone Guy на GPU |
| Media recovery | Повторное подключение внешнего медиаканала и сохранение телефонного вызова при недоступности преобразования |

### 🏗️ Сеть и развёртывание

| Компонент | Назначение |
| --- | --- |
| Caddy | HTTPS/WSS и маршрутизация к внутренним сервисам |
| Docker | Контейнеры телефонных сервисов и Asterisk |
| Terraform (`infra/terraform/`) | Описание инфраструктуры |

## 🛠️ Технологический стек

- Телефонный backend: Go 1.22, Asterisk, ARI, SIP/PJSIP.
- Браузер: React, TypeScript, SIP.js, WebRTC.
- Преобразование голоса: Python, FastAPI, WebSocket, RVC, CUDA.
- Сетевой транспорт: HTTPS, WSS, TURN, TLS и SRTP.
- Развёртывание: Docker и Terraform.

## 📊 Что проверено

| Проверка | Результат |
| --- | --- |
| Звонок между физическими телефонами `1234 → 2015` | 11 октября 2026 года звонок оставался активным не менее 3:44; система восстановила медиаканал четыре раза без сброса вызова. После отбоя Asterisk показал 0 активных каналов и вызовов; пользователь подтвердил, что проблема с обрывом исправлена. |
| Звонок между браузерами | В тесте двумя вкладками одного профиля проверены сигнализация, RTP/RVC-пакеты и завершение вызова. Разговорная разборчивость этим тестом не подтверждалась; полная приёмка с двумя независимыми профилями ещё ожидает проверки. |
| SIP-регистрация физического аппарата из внешней сети | Ожидает проверки с аппарата, действительно подключённого вне VPN. |

Подробные сценарии, даты и ограничения приведены в
[журнале приёмки](docs/BROWSER_CALL_ACCEPTANCE.md). Проверка регистрации,
сигнализации или счётчиков RTP отдельно не доказывает качество слышимой речи.

## ⚠️ Важная информация

- При сбое RVC звонок может сохраниться с прямым аудио без преобразования Phone Guy.
- RVC обслуживает ограниченное число одновременных сессий; при занятости см. инструкции в [документации по эксплуатации](docs/OPERATIONS.md).
- Не храните SIP-пароли, пароли доступа и ключи в репозитории.
- Админка, ARI и сервис RVC не предназначены для публикации через внешний SIP-маршрут.
- После изменений звонков, SIP, аудио или сетевой маршрутизации выполняйте [приёмку звонков](docs/BROWSER_CALL_ACCEPTANCE.md); сборка и unit-тесты её не заменяют.
