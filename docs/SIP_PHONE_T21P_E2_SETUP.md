# Подключение Yealink SIP-T21P E2

## Что подготовлено

Asterisk и Phone Guy GPT v2 уже работают на отдельной VM209. Телефону нужен
только доступ к приватному адресу `192.168.20.70`: напрямую из домашней LAN или
через роутер с WireGuard. SIP и RTP в публичный интернет не выставлены.

Номера с пасхалками:

| Номер | Голос | Назначение |
| --- | --- | --- |
| `1983` | исходный | реквизитный телефон / обычный участник |
| `1987` | Phone Guy GPT v2 | основной обработанный абонент |
| `2014` | исходный | ещё один обычный участник |

Все набирают одну комнату: **`600`**. Одновременно модель обрабатывает одного
абонента; второй Phone Guy-сеанс будет отклонён без утечки исходного голоса.

## Рингтон реквизитного телефона

На физическом Yealink `1983` выбран пользовательский рингтон
`fnaf_phone_ring_pcma_bitexact.wav`: оригинальный звук из
`fnaf-1-phone-call-sound (1).mp3` до 2.187 секунды и затем ровно **4 секунды
тишины**. При повторе телефона интервал между звуковыми фрагментами составляет
4 секунды.

Файл хранится в `assets/yealink/`. Это WAV, PCMA/A-law (G.711), mono, 8000 Hz,
49 556 bytes; он сформирован без `LIST/INFO` метаданных, которые не умеет
разбирать прошивка Yealink. Это важно: PCM и PCMU-варианты телефон показывал в
списке, но не воспроизводил. Рингтон выбран и глобально (Settings → Preference
→ Ring Type), и прямо для Account 1 (Account → Basic → Ring Type). Настройка
относится к аппарату, а не к Asterisk; при factory reset файл нужно загрузить и
выбрать повторно.

входа. Копия высокого качества на ноутбуке:

### Сценарий для ролика: `1900`

Это внутренний автоматический сценарий, а не номер, который нужно набирать с
Yealink. Виртуальный абонент `2014` звонит на `1900`, телефон `1983` получает

заканчивается.

Запуск с ноутбука, у которого есть SSH-доступ к VM209:

```bash
ssh ubuntu@192.168.20.70 'sudo /usr/local/sbin/start-fnaf-video-sequence'
```

Скрипт получает пароль виртуального `2014` только из runtime на сервере и не
выводит его в терминал.

С Yealink набрать **1987** и вызвать: сервер отвечает и повторяет короткую
8-секундную русскую тестовую запись, уже обработанную Phone Guy GPT v2.
Между повторами пауза 2 секунды. Это проигрыватель, не разговорный AI:
он не распознаёт речь и не отвечает на вопросы. Отбой завершает воспроизведение.
GPU не занят; live-аккаунт `1987` для комнаты `600` сохраняет свой профиль.

Аудио `conference/asterisk/sounds/phoneguy.wav` получено из проверенного
`/opt/voice-rvc/smoke-output/ru-streamed.wav`, приведено к mono PCM16 8000 Hz.
Deploy устанавливает аудио, dialplan и modules в runtime; Compose монтирует
их read-only. Для старых runtime перед обновлением Compose необходимо
установить эти три ресурса. Перезапуск Asterisk выполнять без активных звонков,
затем перезапускать controller и проверять `ari show apps`: нужен `phoneguy-sip`.

2026-09-15: маршрут развёрнут на VM209; SIPp-клиент `2014` позвонил на `1987`,
получил ответ и завершил вызов BYE с exit=0. Проверять слышимость на самом
Yealink отдельно. На первой попытке после пересоздания контейнера телефон
может повторно зарегистрироваться не сразу.

## Что подключить физически

1. Подключить Ethernet к разъёму `Internet` телефона.
2. Подать питание штатным адаптером или совместимым PoE.
3. Дождаться адреса по DHCP и открыть этот адрес в браузере из той же сети.
4. Если телефон сохранил чужую корпоративную конфигурацию, сделать factory
   reset удержанием `OK` примерно 10 секунд и подтвердить сброс.

## Получить актуальные параметры аккаунта

Пароли генерируются при развёртывании и хранятся только на VM209. Команда ниже
показывает один выбранный аккаунт; её вывод нельзя сохранять в Git или скриншотах:

```bash
cd /home/oleg/Documents/voice-changer/.worktrees/fcpe-canary-productization
./deploy/show-sip-phone-setup.sh 1987
```

Для реквизитного телефона без обработки вместо `1987` использовать `1983`.

## Поля Account 1 в Yealink

| Поле Yealink | Значение |
| --- | --- |
| Line Active | Enabled |
| Label / Display Name | любое понятное имя |
| Register Name | номер из команды, например `1987` |
| User Name | тот же номер |
| Password | значение `Password` из команды |
| SIP Server 1 / Server Host | `192.168.20.70` |
| Port | `5060` |
| Transport | `UDP` |
| NAT Traversal | Disabled |

В разделе codecs поднять **PCMA / G.711 A-law** на первое место. STUN, SIP TLS,
outbound proxy и внешний registrar для этой схемы не нужны.

После сохранения Account 1 должен стать `Registered`. Затем снять трубку,
набрать `600` и подтвердить вызов. Второй участник делает то же со своего
softphone или другого SIP-аккаунта.

## Если не регистрируется или нет звука

### Реальный телефон, 2026-09-15

Yealink T21, MAC `00:15:65:89:b3:85`, DHCP `192.168.20.134`, настроен как
`1983` (original), сервер `192.168.20.70:5060`, UDP, NAT/STUN/outbound proxy
выключены. Пароль передан непосредственно из текущего runtime без публикации.
На сервере подтверждён contact `1983/sip:1983@192.168.20.134:5062`.
Регистрация, входящий SIP-вызов и слышимость пользовательского FNaF-рингтона
подтверждены 2026-09-15. Для теста временно добавлялся внутренний номер `1900`,
который вызывал `PJSIP/1983`; после проверки он удалён. В штатном dialplan его
нет.

При первом REGISTER выявлен дефект: AoR `1983-aor` не совпадал с To user
`1983`. Исправлены AoR имена и ссылки для всех трёх номеров в шаблоне и
runtime `20260911T190952Z`; Asterisk перезапущен при нуле активных каналов.
Резервная копия live-конфига: `pjsip.conf.before-yealink-20260915` рядом с ним.
Endpoint и AoR могут иметь одно имя: Asterisk различает их по `type`.
Панель старой прошивки может остаться на «Пожалуйста, подождите» после
успешного сохранения — проверять регистрацию на сервере, не повторять submit
вслепую. После обновления страницы проверить статус и приоритет PCMA.

- Проверить, что телефон видит маршрут до `192.168.20.70` и использует UDP 5060.
- Снова получить текущий пароль: после нового deploy он может измениться.
- Убедиться, что включён PCMA, а не только G.722/G.729.
- Для удалённой площадки проверить WireGuard-роутер рядом с телефоном; сам
  T21P E2 WireGuard не поднимает.
- Не включать публичный port-forward для 5060 или RTP.
- При `busy` убедиться, что другой `1987` уже не говорит; подождать освобождения
  текущего GPU-вызова и позвонить снова.
