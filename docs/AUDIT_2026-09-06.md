# Аудит Phone Line — 2026-09-06

Область: весь небольшой проект — спецификация, браузерный клиент, DSP,
WebSocket/API, зависимости, Docker, Terraform, доставка, сетевые ограничения
и проверки отдельной VM. Исправления находятся в этом локальном репозитории;
запуск выполняется на VM 209. Порог 150 мс отложен по решению пользователя.

## Проверка

- 21 Python-тест: DSP, настройки, протокол, сессии, Origin и HTTP headers.
- 5 Node-тестов: реальный код AudioWorklet и клиентская логика с подменой
  недоступных в Node браузерных устройств.
- `tests/live-audio.cjs` выполняет настоящий код worklet с синтетическим
  тоном через production WSS и проверяет ненулевой выход, кадры и очередь.
- Terraform validate пройден, live plan: **No changes** (VM 209).
- Frigate: healthy, `/mnt/recordings` на mapper, маршрут камер через `.12`.
- Контейнер при потоке: около 40 MiB RAM и менее 10% одного CPU в снимке.
- Private HTTPS работает; public-SNI запрос завершился отказом TLS/HTTP2,
  HTTP 000. Прямой доступ к `.70:8080` с ноутбука — timeout с ростом DROP.

Финальный прямой прогон после перезагрузки: **300 секунд, 15000 отправлено,
15000 получено, 0 underruns, 0 сброшенных кадров**. RMS выходного сигнала
0.10284; RTT p50 5.04 мс / p95 10.22 мс, обработка p95 0.936 мс.
Это транспорт и программный аудиовыход, не акустическая задержка.
Повторный аудит `requirements.lock`: известных уязвимостей не найдено.
21 Python и 5 Node тестов прошли. Есть два предупреждения deprecation
тестового клиента, ошибок тестов нет.

## Границы результата

Первоначально управляемый браузер был недоступен. После подключения
браузера приложения выполнен реальный UI-тест кнопки «Проверить звук»:
AudioContext, AudioWorklet, отправка тона, приём обработанного PCM и
завершение сессии прошли; интерфейс показал 0 прерываний и 0 сброшенных
кадров. Оценка задержки 269 мс, RTT 9 мс, обработка 0.8 мс в снимке.
Реальное разрешение микрофона и акустический выход на наушники пользователя
пока не подтверждены. Предыдущая проверка только WSS была недостаточной
для заявления о работающем микрофонном UI.

Теперь в UI есть «Проверить звук» (4 секунды синтетического тона через сервер),
затем «Начать» для микрофона и индикаторы каждого участка. Это позволяет
завершить физическую проверку на устройстве пользователя без доступа агента
к микрофону. Это не RVC-клонирование тембра и не виртуальный микрофон ОС.

## Финальная топология и проверка перезапуска

Пятиминутный тест через VPS вернул 15000/15000 кадров, но показал 38
прерываний и 457 сбросов очереди при RTT p95 около 1047 мс. Поэтому
аудиоканал перенесён на прямой WSS `vm-voice-1.lan.awesomeio.ru`, UI
сохраняет прежний адрес. Caddy в VM использует проверенный wildcard TLS;
синхронизация сертификата ограниченным SSH-ключом запланирована таймером.
10-секундный прямой тест: 500/500 кадров, RMS 0.102, RTT p95 11.3 мс,
0 прерываний/сбросов. Финальный длительный прогон приведён в разделе проверки.

VM 209 перезагружена после обновления: Docker, Caddy, voice-firewall и
таймер сертификата active, контейнер healthy, GTX 1050 Ti видна с
драйвером 580.173.02. Маршрут VPN восстановился через `.12`.
Frigate после этой перезагрузки healthy. Браузерный тест выполнен после
возврата VM, следовательно проверен и HTTPS/WSS путь после reboot.

Первоначальный план содержал дополнительные документы в homelab и
Ansible-автоматизацию; фактически provisioning выполнен Terraform, доставка
и конфигурация VM — скриптами этого проекта. Полная автоматическая установка
Docker/NVIDIA на свежий гостевой образ пока не реализована; существующая VM
подготовлена, шаги подготовки отражены в deployment log.
