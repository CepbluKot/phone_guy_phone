# Готовые голоса и пресеты — 2026-09-06

Запрос: приблизиться к Phone Guy без ручной настройки пользователем.
Ниже исходное исследование. Позднее в тот же день PhoneGuyfnaf1V1 был
загружен и проверен отдельно на VM 209: см.
[результаты испытания](../experiments/phoneguy/README.md).
В действующую микрофонную демку модель пока не подключена.

## Рекомендация

Испытать готовую RVC-модель Phone Guy FNaF 1 в отдельном контейнере VM 209.
Оставить текущий UI, выбранную задержку и один готовый профиль «Phone Guy».
Параметры pitch/index/RMVPE подобрать при интеграции, убрать в расширенные
настройки. Отдельный профиль «Телефон» остаётся лёгким DSP-резервом.

RVC меняет тембр, тогда как телефонный пресет меняет канал звучания.
Дополнительный фильтр после RVC нужен только если модель сама не воспроизводит
эффект записи: двойная фильтрация может ухудшить разборчивость.

## Проверенные находки

- [C0ttontheBunny/Fnafucnmodels](https://huggingface.co/C0ttontheBunny/Fnafucnmodels/tree/main):
  API Hugging Face подтвердил файл `PhoneGuyfnaf1V1.zip`, 78 678 096 байт.
  LFS SHA256 `1ff846db9b9ab508b15dff3891da113d004047a378662e2acfe1de0abff109de`.
  [Каталог](https://rvc-models.com/t/phone-guy-five-nights-at-freddys-1-rmvpe-og-pretrain-300-epochs/11773)
  описывает его как FNaF 1, RMVPE, 300 эпох. Содержимое архива и качество
  инференса пока не проверены; число эпох не доказывает качество.
- [Sergey004/Phone_Guy](https://github.com/Sergey004/Phone_Guy): автор уже
  применяет RVC для Phone Guy в телефонном боте. Пример настройки:
  RMVPE, pitch 0, index rate 0.6; указаны `.pth` и `.index`.
  Это ориентир для сравнения, а не готовый пресет для найденного архива.
  Бот включает TTS, распознавание, внешнюю LLM и SIP — весь проект переносить
  в нашу микрофонную демку не требуется.
- [w-okada/voice-changer](https://github.com/w-okada/voice-changer): готовый
  клиент/сервер для voice conversion. В актуальном основном README поддержка
  RVC зависит от редакции, поэтому нельзя считать любой последний Linux
  бинарник готовым RVC runtime. Для нашей VM потребуется проверить исходную
  серверную ветку/контейнер либо использовать RVC inference напрямую.
- [RVC Project](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI):
  исходный движок и инструменты обучения/инференса. Возможная основа backend,
  обучение собственной модели для первого эксперимента не требуется.
- [Audacity: Telephone / HelmetRadio](https://forum.audacityteam.org/t/cant-find-telephone-effect-on-graphics-eq/59337):
  готовый Telephone EQ и плагин HelmetRadio для аналогового телефонного эффекта.
  Полезно для DSP-профиля; они сами по себе не дают тембр персонажа.

Старые ссылки `sail-rvc/phoneguy` и `sail-rvc/phone-guy-fnaf-2300` нашлись
в поисковом индексе, но прямые запросы API завершились HTTPError. Не считать
их доступными моделями. Другие каталоги содержат FNaF 2 и Phone Dude, но это
не эквивалент целевому голосу из FNaF 1.

## Что проверить при интеграции

1. Архив, состав весов/index и загрузку без произвольного исполнения pickle.
2. Совместимость PyTorch/CUDA со старой GTX 1050 Ti, доступную VRAM и RAM.
3. Один и тот же короткий русский и английский речевой пример: разборчивость,
   сходство, артефакты на согласных, влияние уже встроенного телефонного фильтра.
4. Скорость обработки чанков: пятисекундная задержка допускает буферизацию,
   но не исправляет среднюю производительность медленнее входного потока.
5. Зафиксировать лучший профиль и скрыть технические регуляторы по умолчанию.

Пока нельзя обещать сходство или пригодность GTX 1050 Ti без запуска модели.
Приоритет — сравнить готовую модель на сервере, а не добавлять ещё ползунки.

Самостоятельный серверный Linux/WebUI-деплой из этих материалов не подтверждён; не замена нашей VM-схеме. Сходство пресета не прослушивалось. |

Рекомендация: испытать Deiteris с найденной моделью Phone Guy, затем w-okada
как запасной вариант. Готовая программа всё равно требует единовременного
выбора модели и настройки аппаратного backend; это задача развёртывания,
а не необходимость пользователю каждый раз крутить параметры.
Не обещать автоматический перенос нашей произвольной 5-секундной задержки:
совместимость с ней следует проверить отдельно при интеграции.
