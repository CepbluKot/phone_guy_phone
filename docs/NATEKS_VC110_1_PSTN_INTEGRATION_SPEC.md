# ТЗ: городская линия через Nateks VC-110-1

## Цель

Подключить одну московскую аналоговую городскую линию к Nateks VC-110-1 и
связать шлюз с существующим Asterisk. Городские вызовы проходят обычным
голосом, без Phone Guy/RVC.

## Требуемое поведение

- Любой настроенный и аутентифицированный IP-телефон владельца может набрать
  московский городской номер и позвонить через Nateks без специального
  префикса.
- Входящий вызов с городской линии звонит только на внутренний номер 2015.
- Ответить на этот входящий вызов можно только с телефона 2015. Не включать
  параллельный вызов других телефонов, группу, перехват или общий номер для
  ответа на этот вызов.
- Внутренние вызовы между IP-телефонами продолжают работать через существующий
  Asterisk/Go-маршрут.
- Городские вызовы используют прозрачный обычный голос без обработки RVC.

## Границы и ограничения

- К Nateks подключена одна аналоговая городская линия; через неё возможен один
  одновременный городской разговор. Второй FXO-порт не считать подключённым.
- Исходящий доступ предоставляется только известным владельцу SIP-устройствам,
  прошедшим аутентификацию. Не разрешать анонимный SIP и не использовать Caller
  ID как подтверждение права на исходящий вызов.
- Разрешать только московские городские номера. Поддерживаемые формы набора и
  преобразование номера в формат, требуемый линией, определить при проверке
  провайдера; отдельный префикс доступа не добавлять.
- Экстренные, международные, платные короткие и междугородние направления не
  входят в это ТЗ.
- Не открывать SIP, RTP или веб-управление Nateks в интернет. SIP/RTP шлюза
  ограничить домашней сетью и адресом Asterisk.
- Не ослаблять шифрование и медиаполитику других телефонов ради совместимости
  шлюза. Для связи шлюз—Asterisk использовать отдельный PJSIP endpoint/context.

## Текущее состояние и предварительные условия

- Сетевое подключение и доступ к веб-интерфейсу Nateks задокументированы в
  [NATEKS_VC110_1_NETWORK_SETUP.md](NATEKS_VC110_1_NETWORK_SETUP.md). SIP,
  аналоговая сигнализация и звонки этим документом не подтверждены.
- Входящий номер выбран владельцем — 2015. При последней проверке Asterisk
  endpoint 2015 был `Unavailable` без контакта; до приёмки нужно подтвердить
  его регистрацию.
- Перед выпуском конфигурации сверить runtime PJSIP/dialplan с репозиторием и
  сохранить действующие настройки 1234, 2015, 2016 и текущих внутренних
  маршрутов.
- До маршрутизации проверить, какой FXO-разъём занят, наличие линии и её
  совместимость с настройками определения вызова и отбоя Nateks.

## Предлагаемая граница реализации

- Nateks выступает FXO↔SIP-шлюзом; Asterisk остаётся сервером регистрации и
  маршрутизации.
- В Asterisk создать отдельный аутентифицированный PJSIP endpoint для Nateks,
  однозначно сопоставленный по адресу/идентичности шлюза, с изолированным
  контекстом входящих вызовов.
- Исходящий набор городских номеров направлять через отдельные более точные
  dialplan-правила, сохранив внутренние номера и существующий Go/ARI-маршрут.
- Входящий маршрут направлять прямо на PJSIP/2015 без группы вызова и
  возможности ответа с других endpoint.
- Закрепить адрес шлюза через DHCP-резервирование и ограничить его доступ
  сетевыми правилами до SIP/RTP Asterisk и локального управления.
- Выпустить изменение штатным скриптом SIP-релиза с резервной копией и
  проверенным откатом. Не перезаписывать runtime-конфигурацию шаблоном без
  проверки расхождений.

## Приёмка

1. 2015 зарегистрирован в Asterisk; вызов с другого IP-телефона на 2015 имеет
   двусторонний звук и корректно завершается.
2. С каждого разрешённого владельцу IP-телефона можно позвонить на московский
   городской номер без отдельного префикса; двусторонний звук и отбой работают.
3. Входящий городской вызов звонит только на 2015; другой IP-телефон не может
   ответить на него через перехват, общую регистрацию или группу.
4. Внутренние звонки по-прежнему проходят через существующий Go/ARI-маршрут.
5. Занятость единственной городской линии обрабатывается корректно; Caller ID,
   определение отбоя и DTMF проверены, если линия их предоставляет.
6. Выполнена обязательная браузерная приёмка проекта из
   [BROWSER_CALL_ACCEPTANCE.md](BROWSER_CALL_ACCEPTANCE.md), а Asterisk после
   выпуска здоров и не имеет зависших каналов.

## Открытые технические проверки

- Текущий адрес/MAC Nateks и DHCP-резервирование.
- Конкретный FXO-порт, состояние линии, Caller ID и параметры обнаружения отбоя.
- Требуемый оператором формат номера для исходящей городской линии.
- Регистрация телефона 2015 и фактические двусторонние городские вызовы.
- Runtime-отличия PJSIP, dialplan и firewall от файлов репозитория.
